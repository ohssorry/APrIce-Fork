# 담당 A(가영) - 탐지 엔진 단기간 계획

> 엑셀 역할표의 `COMMON-01`, `COMMON-03`, `CORE-01`~`CORE-04`를 현재
> Python 구조에 맞게 옮긴 계획입니다. 8월 29일 기능 동결 전에는 탐지 범위와
> 정확도를 증명하는 데 집중합니다.

## 소유 파일

```text
src/aprice/detector.py
src/aprice/rules.py
tests/test_detector.py
tests/fixtures/
```

- B 소유인 `pricing.py`, `prices/*.yaml`은 수정하지 않습니다.
- C 소유인 `report.py`, `cli.py`, `.github/`, `docs/`는 수정하지 않습니다.
- 공용 파일 `models.py`가 필요하면 코드를 바꾸지 말고 먼저 이슈로 제안합니다.

## 이번 기간의 완료 기준

- 비용이 발생하는 주요 SDK 호출을 AST로 탐지합니다.
- 주석과 문자열에 적힌 가짜 호출은 탐지하지 않습니다.
- 탐지 기능마다 정상·오탐 방지 테스트가 있습니다.
- 전체 `pytest`, `ruff check .`, `ruff format --check .`가 통과합니다.

## 필수 작업

| 순서 | 작업 | 완료 조건 |
|---|---|---|
| A-01 | 누락된 SDK 호출 추가 | OpenAI 임베딩·이미지·음성·레거시 completion, Anthropic batch, Google embedding 탐지 |
| A-02 | 탐지 정확도 테스트 보강 | 주석·문자열·동명 함수 오탐 방지와 async·중첩 루프 테스트 |
| A-03 | 재시도 루프 구분 | 리터럴 `range`만 횟수를 표시하고 변수 기반 반복 횟수는 추측하지 않음 |

### A-01 - 누락된 SDK 호출 추가

`CALL_SIGNATURES`는 점 경로의 꼬리로 비교합니다. 무관한 `create()`까지 잡지 않도록
가능하면 두 단계 이상의 경로를 사용합니다. 새 시그니처마다 테스트를 하나씩
추가합니다.

### A-02 - 탐지 정확도 테스트 보강

다음 사례를 테스트로 고정합니다.

- 주석과 문자열 속 SDK 호출은 탐지하지 않음
- 이름만 같은 일반 함수는 탐지하지 않음
- async 호출, 중첩 루프, 깨진 Python 파일을 처리함
- 확실하지 않은 SDK 호출은 경고하지 않음

### A-03 - 재시도 루프 구분

`range(5)`처럼 코드에 직접 적힌 상한만 메시지에 사용할 수 있습니다.
`range(n)`이나 `while True`에는 임의의 횟수를 붙이지 않습니다. 기존
`call-in-loop`와 같은 원인을 중복해서 경고하지 않도록 테스트합니다.

## 시간이 남을 때만

- 같은 파일 안에서 루프가 호출하는 함수 1단계 추적
- `**kwargs` 전용 상태가 필요하면 `models.py` 변경 이슈 작성

필수 작업이 끝나기 전에는 크로스 파일 호출 그래프나 깊은 재귀 추적을 시작하지
않습니다.

## 작업 단위

각 행을 별도 이슈와 별도 `feat/...` 또는 `test/...` 브랜치로 진행합니다.
작업 중 의미 있는 단위마다 한글 커밋과 push를 남기고, `develop` 대상 PR에
테스트 결과를 적습니다. 승인 1명 전에는 머지하지 않습니다.
