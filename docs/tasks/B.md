# 담당 B(은지) - 가격 데이터베이스 단기간 계획

> 엑셀 역할표의 `COMMON-02`, `BACKEND-01`~`BACKEND-05`를 현재 Python 구조에
> 맞게 옮긴 계획입니다. 8월 29일 기능 동결 전에는 공식 출처가 있는 가격만
> 제공하고, 잘못된 가격표가 CI를 통과하지 못하게 만드는 데 집중합니다.

## 소유 파일

```text
src/aprice/pricing.py
src/aprice/prices/*.yaml
tests/test_pricing.py
```

- A 소유인 `detector.py`, `rules.py`는 수정하지 않습니다.
- C 소유인 `report.py`, `cli.py`, `.github/`, `docs/`는 수정하지 않습니다.
- 공용 파일 `models.py`가 필요하면 코드를 바꾸지 말고 먼저 이슈로 제안합니다.

## 이번 기간의 완료 기준

- `0.00` 자리표시자 대신 공식 페이지에서 확인한 가격만 남습니다.
- 가격마다 출처와 확인 날짜를 PR에 기록합니다.
- 가격표 누락·중복·음수·잘못된 날짜를 테스트가 잡습니다.
- 전체 `pytest`, `ruff check .`, `ruff format --check .`가 통과합니다.

## 필수 작업

| 순서 | 작업 | 완료 조건 |
|---|---|---|
| B-01 | OpenAI 가격표 정리 | 공식 출처로 확인한 모델만 등록하고 `verified_on` 기록 |
| B-02 | Google 가격표 정리 | 기본 구간 가격과 장문 구간 주의사항을 함께 기록 |
| B-03 | YAML 스키마 검증 | 필수 필드·중복·음수·0원 자리표시자·날짜 형식 자동 검사 |

### B-01 - OpenAI 가격표 정리

기억이나 검색 결과 요약으로 가격을 채우지 않습니다. OpenAI 공식 가격 페이지에서
직접 확인한 값만 사용하고, 확인하지 못한 모델은 `0.00`으로 남기지 말고 항목에서
제외합니다. PR 본문에 출처 URL과 확인 날짜를 적습니다.

### B-02 - Google 가격표 정리

Google 공식 가격 페이지에서 직접 확인합니다. 현재 모델이 구간별 가격을 완전히
표현하지 못하면 기본 구간만 넣고 `note`에 장문 요청의 가격이 달라질 수 있음을
명시합니다. 구조 변경은 별도 이슈로 넘깁니다.

### B-03 - YAML 스키마 검증

모든 가격 YAML을 자동 순회하여 다음을 확인합니다.

- `id`, 입력 단가, 출력 단가, `verified_on` 존재
- 가격이 음수가 아니며 자리표시자 `0.00`이 아님
- 모델 `id`가 중복되지 않음
- 확인 날짜가 `YYYY-MM-DD` 형식이며 미래가 아님
- 로딩 실패 시 파일명과 항목을 알 수 있는 오류를 제공함

## 시간이 남을 때만

- `verified_on` 기반 오래된 가격 경고를 위한 공용 모델 변경 이슈
- 공식 출처가 확보된 국내 API 1종 조사
- 캐시·배치 할인 가격 범위를 위한 설계 이슈

필수 작업이 끝나기 전에는 호출량, 월 비용, 캐시 적중률을 가정하는 기능을 시작하지
않습니다.

## 작업 단위

각 행을 별도 이슈와 별도 `feat/...` 또는 `test/...` 브랜치로 진행합니다.
작업 중 의미 있는 단위마다 한글 커밋과 push를 남기고, `develop` 대상 PR에
공식 출처와 테스트 결과를 적습니다. 승인 1명 전에는 머지하지 않습니다.
