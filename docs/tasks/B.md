## B-001 — OpenAI 가격표 채우기

**문제.** `src/aprice/prices/openai.yaml`의 값이 전부 `0.00` 자리표시자입니다.
README에도 `⚠️ placeholder`로 표시돼 있습니다. 지금 상태로는 OpenAI 호출이
`$0.00000 - $0.00000`으로 나옵니다. **틀린 숫자를 자신 있게 보여주는 건
숫자를 안 보여주는 것보다 나쁩니다.**

**할 일.** OpenAI 공식 가격 페이지에서 확인해 채웁니다.

```yaml
- id: gpt-4o
  input_per_mtok: 0.0      # ← 공식 페이지 값으로
  output_per_mtok: 0.0     # ← 공식 페이지 값으로
  verified_on: null        # ← 확인한 날짜 (YYYY-MM-DD)
```

**철칙 — 기억으로 채우지 마세요.** LLM은 가격을 그럴듯하게 지어냅니다. 반드시
공식 페이지를 열어서 눈으로 확인한 값만 씁니다. 확인 못 한 모델은 **아예 빼세요.**
없는 모델은 `unpriced`로 정직하게 보고되지만, 틀린 가격은 조용히 거짓말합니다.

**PR에 출처 링크를 반드시 넣으세요.** 근거 없는 가격은 리뷰가 불가능합니다.
이건 외부 기여자에게도 똑같이 요구할 규칙이라, 우리가 먼저 지켜야 합니다.

**완료 조건**
- [ ] 주요 모델 가격이 공식 출처 기준으로 채워짐
- [ ] 모든 항목에 `verified_on` 날짜 기입
- [ ] 확인 못 한 모델은 삭제 (0.00으로 남기지 않음)
- [ ] PR 본문에 출처 URL
- [ ] `README.md`의 `⚠️ placeholder` 표시 갱신은 **C에게 이슈로 요청** (README는 C 소유)
- [ ] `pytest` · `ruff check .` 통과

**에이전트에 붙여넣을 프롬프트**

```
AGENTS.md와 docs/architecture.md를 먼저 읽어라.
docs/tasks/B.md의 B-001 작업을 수행한다.
src/aprice/prices/openai.yaml의 더미 가격을 채운다.
중요: 가격을 기억으로 채우지 마라. 웹에서 OpenAI 공식 가격 페이지를 열어
확인한 값만 쓰고, 확인하지 못한 모델은 항목째 삭제하라.
각 항목에 verified_on 날짜를 넣고, 사용한 출처 URL을 마지막에 보고하라.
prices/*.yaml과 tests/test_pricing.py 외의 파일은 수정하지 마라.
```

## B-002 — Google 가격표 채우기

B-001과 동일한 작업을 `src/aprice/prices/google.yaml`에 합니다.

**Google 특유의 함정.** Gemini는 **프롬프트 길이에 따라 단가가 바뀌는** 구간별
가격을 씁니다(예: 128k 토큰 초과 시 단가 인상). 현재 `Price` 구조에는 구간 개념이
없습니다.

**이번 작업에서는 구조를 바꾸지 마세요.** 낮은 구간(기본 단가)만 채우고,
`note` 필드에 사실을 적어둡니다.

```yaml
- id: gemini-2.5-pro
  input_per_mtok: 0.0
  output_per_mtok: 0.0
  verified_on: 2026-08-20
  note: "Price shown is the base tier; long-context requests are billed higher."
```

`note`는 이미 `Price`에 있는 필드라 `models.py`를 건드릴 필요가 없습니다.
구간별 가격을 제대로 지원하는 건 별도 이슈로 남기세요 — **8/29 전에 손대기엔
위험한 구조 변경입니다.**

**완료 조건**
- [ ] 기본 구간 가격이 공식 출처 기준으로 채워짐
- [ ] 구간제 모델은 `note`에 명시
- [ ] 구간별 가격 지원 이슈를 GitHub에 등록 (향후 과제로)
- [ ] PR 본문에 출처 URL

## B-003 — 가격표 스키마 검증 테스트

**문제.** 지금은 YAML에 오타가 있어도 런타임에야 터집니다. `load_prices()`가
`entry["id"]`, `float(entry["input_per_mtok"])`로 직접 접근하기 때문에
필드가 빠지면 `KeyError`가 그대로 올라옵니다.

**게다가 이 프로젝트는 외부인의 YAML PR을 받는 걸 전략으로 삼고 있습니다.**
기여자가 실수했을 때 CI가 친절하게 잡아주지 못하면 그 전략이 작동하지 않습니다.

**할 일.** `tests/test_pricing.py`에 **모든 YAML 파일을 순회하는** 검증 테스트를
추가합니다.

검사할 것:
- 필수 필드 존재: `id`, `input_per_mtok`, `output_per_mtok`, `verified_on`
- 가격이 음수가 아님
- **가격이 `0.00`인 더미가 남아있지 않음** (B-001·B-002 회귀 방지)
- `id` 중복 없음
- `verified_on`이 `YYYY-MM-DD` 형식이고 미래 날짜가 아님
- `load_prices()`가 모든 파일을 예외 없이 읽어냄

추가로 `pricing.py`의 로더가 잘못된 항목을 만났을 때 **어느 파일 어느 항목인지**
알려주도록 에러 메시지를 개선하세요. 지금은 `KeyError: 'id'`만 나옵니다.

**완료 조건**
- [ ] YAML 파일을 자동 순회 (파일이 늘어도 테스트 수정 불필요)
- [ ] 위 항목 전부 검사
- [ ] 일부러 깨뜨린 YAML로 테스트가 실제로 실패하는지 확인
- [ ] 로더 에러 메시지에 파일명·모델 id 포함
- [ ] `pytest` · `ruff check .` 통과

> 이 작업이 끝나면 **외부 기여자의 가격 PR을 CI가 자동 검수**합니다.

## B-005 — 국내 API 가격표

**왜 하는가.** 해외 도구들이 절대 안 하는 영역입니다. **국내 대회에서 이건
"우리만 있는 것"이고, 심사위원에게 즉시 전달되는 차별점입니다.**

**할 일.** `src/aprice/prices/` 에 새 파일을 추가합니다.

후보 (하나만 제대로 해도 충분합니다):
- **네이버클라우드 HyperCLOVA X** — 국내 LLM, 토큰 단가 구조라 잘 맞음
- **카카오 로컬/맵 API** — 호출 건당 과금
- **토스페이먼츠 / 기타 결제** — 건당 수수료

**중요한 구조 문제.** 카카오맵 같은 API는 **토큰이 아니라 호출 건당** 과금입니다.
`Price`에 `unit` 필드가 이미 있고 기본값이 `"token"`입니다. 여기에 `"call"`을
쓰면 `models.py` 변경 없이 표현할 수 있습니다.

다만 `pricing.estimate()`가 지금은 토큰 단가만 계산합니다. `unit == "call"`인
경우의 분기를 `pricing.py`에 추가하세요 — **이건 B 소유 파일이라 자유롭게
고쳐도 됩니다.**

건당 과금이면 비용이 범위가 아니라 **정확한 단일 값**입니다. `low == high`로
두면 기존 구조 그대로 표현됩니다.

또한 **A에게 탐지 시그니처 추가를 이슈로 요청해야 합니다.** 가격표만 있고
`CALL_SIGNATURES`에 없으면 호출 자체가 안 잡힙니다. **B-005를 시작할 때 바로
이슈를 여세요** — A의 작업 대기 시간이 생깁니다.

**완료 조건**
- [ ] 국내 API 최소 1개 가격표 (공식 출처 확인, `verified_on` 기입)
- [ ] `unit: call` 계산 분기 + 테스트
- [ ] A에게 탐지 시그니처 이슈 등록
- [ ] `pytest` · `ruff check .` 통과

## B-006 — 캐시·배치 할인 단가

**문제.** 실무에서 비용을 가장 크게 좌우하는 두 가지가 빠져 있습니다.

- **프롬프트 캐싱** — 캐시 히트 시 입력 단가가 대폭 낮아짐
- **배치 API** — 통상 50% 할인

지금은 둘 다 정가로 계산합니다. **캐싱을 쓰는 코드의 비용을 실제보다 크게
보고합니다.**

**할 일.**

1. YAML 스키마에 선택 필드 추가:
   `cached_input_per_mtok`, `batch_discount`
2. `Price`에 대응 필드 추가 — **`models.py` 변경이므로 이슈 먼저 🔒**
3. `estimate()`에 반영. 단, **캐시 히트율은 소스코드에서 알 수 없습니다.**

**여기가 프로젝트 원칙과 부딪히는 지점입니다.** "캐시 히트율 50% 가정" 같은
숫자를 지어내면 안 됩니다. 대신 이렇게 하세요.

- 하한(`low`)에 캐시 최대 활용을, 상한(`high`)에 캐시 미사용을 반영해
  **범위를 넓히는** 방식으로 표현합니다. 이건 지어낸 게 아니라 실제 가능 범위입니다
- 또는 `--assume-cache-hit` 같은 **사용자가 명시적으로 켜는 플래그**로 둡니다
  (CLI 플래그는 C 소유 — 이슈로 협의)

**완료 조건**
- [ ] `models.py` 변경 이슈 승인
- [ ] 캐시 단가가 있는 모델에서 범위가 올바르게 넓어짐
- [ ] 캐시 단가가 없는 모델은 기존과 동일하게 동작 (회귀 없음)
- [ ] 히트율을 임의 가정하지 않았음이 코드와 주석에서 분명함
- [ ] `pytest` · `ruff check .` 통과
